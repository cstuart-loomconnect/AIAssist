REVIEW CHECKLIST 1: OBJECT MODEL
================================

Objects are in dependency order: a parent is always checked before the objects that look up to it, so each relationship is checked once, from the child side, against a parent already signed off.

Each object carries its own trigger, handler and handler test, so an object is finished only when what enforces it on save is finished too.

1.3.4 AIUsage__c (AI Usage)
~~~~~~~~~~~~~~~~~~~~~~~~~~~

Sharing: ReadWrite (external Private). Name field: AutoNumber. Field history: off.
What it is: what one user has used of AI Assist today. One record per user, written only by the platform. The limits it is checked against stay on AIUsagePolicy__c.
Day: the org's calendar day. A record dated an earlier day counts as zero and is started again on the user's next use, so no scheduled job is needed to reset it.
Written by: AIConversationMessageTriggerHandler (tokens) and AIConversationTriggerHandler (conversations started), through AIUsageService. Read by AIUsageLimitService.

1.4.3 Execution trace (no longer an object)
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

What ran to produce a reply is one JSON array in AIConversationMessage__c.ExecutionTraceJson__c (131,072 characters), not a record per step. Each entry has step, stepType (Prompt Assembly, Template Match, Data Source, Provider Call, Workflow Action, PII Masking, Other), status, ms and a stepDetail that names the template, data source or masked fields (never values). Administrators' entries also carry provider, model, what was sent, iteration and attempt counts, and workflow action and confirmation details. Debug payloads are in DebugRequestJson__c, DebugResponseJson__c and DebugSentPreviewText__c on the same message. Written by AIExecutionStepRecorder.

[ ] Access in each permission set (field) is correct: read only, because only Apex writes the trace
